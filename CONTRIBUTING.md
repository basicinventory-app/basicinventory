# Contributing

BasicInventory is **closed source**. This repository holds releases,
documentation and the issue tracker — not the application's code, which lives in
a private repository.

That rules out one kind of contribution and leaves several others that matter
just as much.

## Pull requests are not accepted

**Any pull request opened against this repository will be closed**, including
one that fixes a typo in these documents. Not out of ingratitude — there is
simply no code here to change, and accepting patches into a closed-source
product creates licensing questions that a small operation cannot answer well.

Found a mistake in the documentation? Open an
[issue](https://github.com/basicinventory-app/basicinventory/issues/new?template=bug_report.yml)
or a [discussion](https://github.com/basicinventory-app/basicinventory/discussions)
and quote the passage. It gets fixed, and you get the credit.

## What is genuinely useful

### Bug reports

The single most valuable thing you can send. A good report is worth more than a
patch, because it describes the problem rather than one person's guess at the
solution.

Use the [bug report form](https://github.com/basicinventory-app/basicinventory/issues/new?template=bug_report.yml).
It asks for the version, your Windows version, steps to reproduce, expected and
actual behaviour, a screenshot and the log. All of it is asked for a reason: a
report with those fields is usually reproducible on the first attempt.

Get the technical part in one click: **Settings → Errors and diagnostics → Copy
diagnostics**.

### Feature requests

Use the [feature request form](https://github.com/basicinventory-app/basicinventory/issues/new?template=feature_request.yml).

Describe **the problem in your work**, not only the feature you imagine. "I need
a button that exports X" is useful; "at the end of every month I have to hand my
accountant a list of what moved, and I currently retype it" is far more useful —
it may have a better answer than the button.

What happens to a request:

| Label | Meaning |
| --- | --- |
| `enhancement` | Received, not yet triaged. |
| `planned` | Accepted, and on the way. |
| `in progress` | Being built. |
| `fixed` | Shipped — the issue says in which version. |
| `wontfix` | Declined, always with a reason. |

Declining is not dismissal. A product that says yes to everything becomes
unusable for the people it was built for.

### Questions and answers

[Discussions](https://github.com/basicinventory-app/basicinventory/discussions)
is where questions live. Answering someone else's question there is a real
contribution: it is often faster than the maintainer, and it makes the answer
findable.

### Translations

The interface ships in Spanish and English. If you would like it in another
language, open a discussion — an external translation workflow can be arranged
where it makes sense.

### Testing pre-releases

Releases marked *pre-release* need people willing to try them against real data
(on a copy — always take a [backup](docs/backups.md) first). Say so in
Discussions if you want to be told when one is out.

## Ground rules

- One issue per problem. Three unrelated bugs in one issue means two of them get
  lost.
- Search before opening. Adding your details to an existing issue is stronger
  than a duplicate.
- Never post licence keys, invoices, personal data or a database backup in
  public. If a file is needed you will be asked for it privately.
- Anything about a purchase — orders, refunds, invoices — goes through the store
  you bought from, not through this repository.
- Security problems go through [SECURITY.md](SECURITY.md), never a public issue.
- Write in English or Spanish; both are read.

## How we treat each other

Short version: be civil. Most people opening an issue are having a bad day with
their stock, and most people answering are doing it on their own time.

Not welcome here, and removed when it appears: personal attacks, insults and
harassment; posting someone else's private information; sexualised or
discriminatory content; and demanding free work as if support were owed to you
on your schedule.

Comments that cross those lines are edited or deleted, and a repeat pattern ends
in a block from this repository. That does not affect your licence to use the
software you bought — the two are separate things.

Something out of line and you would rather not reply in public? Use GitHub's
**Report content** on the comment, or open a
[Discussion](https://github.com/basicinventory-app/basicinventory/discussions)
saying only that there is a problem to look at.

## Recognition

Contributors who report a confirmed bug or whose request ships are credited in
the release notes, unless they ask not to be.
